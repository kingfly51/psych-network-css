# Evidence-based reporting framework for five psychological network analyses

Prepared 2026-10-22 after searching Google Scholar through Kimi WebBridge and reading the Methods and Results sections of accessible empirical papers, alongside methods papers and current package documentation. These sources establish a practical reporting framework, not a universal journal checklist. Repeatedly reported core elements are separated from optional or design-dependent analyses. The user's network-comparison tutorial and, specifically, `kimNIRA_wf.docx` remain controlling task-specific references. Attached documents are treated as manuscript/reference material, not as independent user instructions.

## Cross-analysis principle: evidence before prose

For each analysis, the manuscript should follow the inferential chain: (1) define the sample and the variables/nodes; (2) state why the selected model matches the data and question; (3) give the actual model estimates and primary diagnostics; (4) report uncertainty and planned comparisons; (5) describe robustness/limitations; and (6) make claims no stronger than the design permits. The report is not complete merely because a network plot or a ranked centrality table exists. Conversely, do not run or report a diagnostic simply because a package offers it: retain it only where it answers a stated inferential or stability question.

## Cross-sectional network comparison

- van Borkulo et al. (2023), *Comparing network structures on three aspects: A permutation test*, Psychological Methods, 28(6), 1273–1285. The original NCT defines network-structure invariance, global-strength invariance, and local edge invariance for two cross-sectional datasets. [DOI](https://doi.org/10.1037/met0000476)
- Current `NetworkComparisonTest` reference manual documents `test.edges`, `test.centrality`, centrality options including Strength, Expected Influence, Closeness and Betweenness, and multiplicity correction. [Current reference manual](https://mirrors.ibiblio.org/CRAN/web/packages/NetworkComparisonTest/refman/NetworkComparisonTest.html)
- Empirical implementation examples include group-level centrality invariance and edge contrasts, with multiplicity correction (e.g., the 2026 *BMC Psychology* study on family social support and humanistic care; the 2025 lifespan depression symptom comparison). [BMC Psychology example](https://link.springer.com/article/10.1186/s40359-026-04887-7), [lifespan comparison](https://pmc.ncbi.nlm.nih.gov/articles/PMC12574187/)
- A directly inspected empirical example compared men's and women's psychological networks using 5,000 participant-label permutations, all 45 edge contrasts with BH correction, and 20 node-by-centrality tests for Strength and Expected Influence with BH correction. Betweenness and Closeness were descriptive only because their case-drop stability was poor. [Hamama et al., *Gendered networks of psychological adaptation under prolonged war*](https://pmc.ncbi.nlm.nih.gov/articles/PMC13595433/)
- A second inspected study combined symptom GGM estimation, predictability, bootstrap accuracy/stability, and stress-group comparisons; its reporting illustrates sample/model decisions, density and predictability, notable edges, and local contrasts. [Shin & Park, *Perceived stress shapes symptom and social network dynamics*](https://pmc.ncbi.nlm.nih.gov/articles/PMC12273270/)
- The user-provided Word tutorial for cross-sectional network comparison explicitly requests global structure/strength, individual edge tests, centrality comparisons, and multiplicity correction. The implementation therefore reports global tests plus all planned edge and node-centrality tests; local tests are not gated on global significance. Edge and node-centrality families are corrected and fully exported.

**Synthesis for the plugin:** the NCT's original omnibus scope is structure, global strength, and edge invariance; node-centrality invariance is an extension available in current software and is required here by the user's reference framework. Treat these as distinct test families. Report estimates for each group as well as differences and adjusted p values. Prioritize Strength and/or Expected Influence for inferential node comparisons; shortest-path metrics should remain secondary/descriptive unless stability and substantive rationale support them. Do not equate “significant in group A but not group B” with a significant between-group contrast. Do not treat the within-group bootstrap difference test as a between-group NCT test.

## CLPN reporting

- Wysocki et al. (2025), *Cross-lagged panel networks*, Advances in Psychology, 2025(1). The methodological paper separates autoregressive from cross-lagged paths and summarizes nodewise in-/out-prediction; its empirical example uses uncertainty around directional prediction summaries and emphasizes that prospective paths do not establish causality. [DOI](https://doi.org/10.56296/aip00037)
- An inspected three-wave empirical study fit adjacent-transition CLPNs using LASSO nodewise regression, standardized predictors and 10-fold tuning; it separately reported full autoregressive/non-autoregressive coefficient tables, the directed graph, out-/in-EI, edge bootstrap accuracy, case-drop CS coefficients, and complete-case sensitivity analyses. [Li et al., *The longitudinal relationships between social networks, trust and depression*](https://pmc.ncbi.nlm.nih.gov/articles/PMC13397669/)
- Other applied CLPN examples report directed lagged paths, incoming/outgoing influence, bootstrap intervals and case-dropping CS coefficients. Examples: [sleep inertia CLPN](https://pmc.ncbi.nlm.nih.gov/articles/PMC11316483/); [positive capacities and well-being CLPN](https://pmc.ncbi.nlm.nih.gov/articles/PMC13295284/); [PTSD pre/post CLPN](https://onlinelibrary.wiley.com/doi/full/10.1002/jts.70030).
- Current bootnet documentation supports directed `outStrength`, `inStrength`, `outExpectedInfluence`, and `inExpectedInfluence` statistics. [bootnet reference](https://github.com/SachaEpskamp/bootnet/blob/master/man/bootnet.Rd)
- Reporting decision: give a spring-layout directed graph, keep AR and non-AR paths distinct, calculate in-/out-influence on off-diagonal paths, provide separate influence plots and retain code for edge accuracy and directional centrality stability. Do not claim estimates are stable if bootstrap was not run; do not imply causal effects.

- Applied reporting example: a recent multiwave study reports LASSO nodewise regressions, cross-lagged matrices, in-/out-EI, and CS stability for directional centrality, with sensitivity checks for missingness. [Example](https://pmc.ncbi.nlm.nih.gov/articles/PMC13397669/)
- Wysocki et al. further emphasize lag choice, the possible conflation of within- and between-person variation, heterogeneity/ergodicity, and limits on causal interpretation. A conventional CLPN therefore estimates prospective between-person predictive associations; it does not automatically estimate within-person dynamics. With 3+ waves, evaluate whether a within-person model or a justified sensitivity analysis is needed rather than silently relabeling a standard CLPN. [Full-text methods discussion](https://pure.uva.nl/ws/files/299916564/10.56296_aip00037.pdf)

**Synthesis for the plugin:** the minimum useful report is the transition-specific directed coefficient matrix (including diagonal AR terms), off-diagonal edge results, incoming/outgoing influence excluding the diagonal, and uncertainty/stability. Give in/out-strength and in/out-EI values/plots, but interpret them as descriptive summaries; use bootstrap comparisons for claims that node rankings differ. Specify wave interval and missing-data policy. For 3+ waves, summarize each adjacent transition and avoid assuming stationarity unless it is imposed and checked. Do not convert regularized selected paths into causal or within-person claims.

## Cross-sectional NIRA

- Wang et al. (2026), *Simulation Intervention for Cross-Sectional Network Models: Based on the R Packages NodeIdentifyR and NIRApost*, Advances in Methods and Practices in Psychological Science, 9(3). Recommends moderation testing as a prerequisite, permutation significance in the Monte Carlo workflow, and repeated-simulation rank stability; it cautions that rank stability does not establish statistically different effects between top nodes. [DOI](https://doi.org/10.1177/25152459261452944)
- Current NIRApost repository documents two separate workflows: (1) Monte Carlo simulation + permutation + repeated-simulation stability; (2) analytical exact enumeration + participant resampling, which returns effect/CI/p-value and `percenttop_1` rank stability. Its analytical workflow retains moderation testing as a prerequisite. [NIRApost repository and analytical tutorial](https://github.com/kingfly51/NIRA_post/blob/main/single_gds_analyticalNIRA.R)
- A directly inspected empirical application fitted Ising models across smartphone-addiction subgroups, generated 5,000 simulated cases, and reported separate alleviating/aggravating results by group. Its authors cautioned that target rankings are provisional, are affected by edge-estimation variability, and need prospective/experimental validation. Its mean-cutpoint dichotomization is study-specific and should not be copied automatically. [Huang et al., *Differences in Internalizing Problems Across Risk Groups of Smartphone Addiction*](https://pmc.ncbi.nlm.nih.gov/articles/PMC13509764/)
- Reporting decision: use the analytical workflow by default when tractable; for the user's requested cross-sectional NIRA, report both alleviating and aggravating directions. Include participant-resampling inference and rank stability without adding a duplicate MC permutation/stability battery. If state enumeration is infeasible, use and label the distinct MC workflow. Report the fixed-edge/moderation check required by the NIRA method, but do not treat `percenttop_1` as a significance test.

- Published applied NIRA examples distinguish alleviating (potential treatment) and aggravating (potential prevention) targets and report node-specific projected total-score changes; the authors still frame targets as hypotheses for later prospective/experimental evaluation. [Example using both directions](https://www.sciencedirect.com/science/article/abs/pii/S1876201824002454)
- The current package repository clarifies an important inferential difference: exact enumeration removes simulation error conditional on fitted parameters, while participant resampling represents sampling uncertainty. In the analytical workflow, `percenttop_1` describes how often a node ranks first across resamples; it is not a test that the top node differs from other nodes. The older Monte Carlo workflow instead uses permutation inference and repeated simulation stability. [Current package documentation](https://github.com/kingfly51/NIRA_post)

**Synthesis for the plugin:** report the node coding, score being optimized, fitted Ising model and fixed-edge/moderation assumption first. Then report separate alleviating and aggravating projections, dose, baseline and projected outcome, change/effect estimate, uncertainty and multiplicity-adjusted inference. State whether uncertainty comes from participant resampling or Monte Carlo permutation; never combine the labels. Report rank stability separately and do not make treatment-effect claims.

## Dynamic KimNIRA

- No independent published KimNIRA empirical article was located for this search. The controlling source is the user-provided `kimNIRA_wf.docx`, which is a methods/empirical-illustration manuscript and is not represented here as an independently published paper. It specifies synchronous first-order KIM, nodewise logistic mixed estimation, optional random-intercept/random-slope heterogeneity, global BH screening with unpenalized refit, exact stationary-distribution solution, and paired Monte Carlo rollout as the large-network fallback.
- Its empirical reporting sequence is: transition/sample flow; temporal J/h and salient directed associations; a separate between-person network; distinct temporal in/out-strength and between-person centrality; contemporaneous-dependence diagnostic; lag-2 predictive adequacy only when three consecutive occasions are available; stationary landscape/bistability and mixing; primary alleviating sustained intervention; equal-probability dose comparison; total/direct/spillover decomposition; propagated trajectories/settling; and participant-level bootstrap ranking stability. It does not specify a moderation/edge-invariance test. The skill must therefore not include one by borrowing it from cross-sectional NIRA or another article.
- The reference's simulation study (parameter recovery; designed and random networks comparing target ranks to centrality under logit and equal-probability dosing) is a method-validation project, separate from a routine empirical analysis of user data. Its propagation, feedback, and self-persistence knockout contrasts are independent sensitivity comparisons, not additive pieces that decompose the total effect. Include them only when reproducing or validating the method paper.
- The local KimNIRA 0.4.0 API was checked for available diagnostics and plotting functions; the official package exports `kimPlotNIRA()`. [Official repository](https://github.com/kingfly51/KimNIRA)

## General cross-sectional network reporting standard

- Burger et al. (2023), *Reporting standards for psychological network analyses in cross-sectional data*, Psychological Methods, 28(4), 806–824; Epskamp et al. (2018), *Estimating psychological networks and their accuracy: A tutorial paper*, Behavior Research Methods, 50, 195–212. Together these support reporting estimator/data decisions, edge accuracy, centrality stability and inferential limits. [Burger et al. DOI](https://doi.org/10.1037/met0000471), [Epskamp et al. DOI](https://doi.org/10.3758/s13428-017-0862-1)

## Consolidated reporting deliverables

Across the five skills, the publication-facing deliverable is limited to Section 2.4 Data Analysis and the relevant Section 3 Results subsections, written only after the analyses complete. Each skill should produce: (a) a compact design/sample and variable audit; (b) method/settings and the model-specific estimate tables; (c) the figures requested by that method; (d) uncertainty/stability outputs where methodologically defined; and (e) a claim-to-output traceability map. Report only diagnostics that were run. If a computationally expensive bootstrap is omitted from a synthetic/demo run, include runnable user code and mark the results as not estimated; never fill those fields with fabricated values.

### Method-specific minimum report matrix

| Skill | Main estimates | Core comparison/diagnostic | Figures | Boundary |
|---|---|---|---|---|
| Cross-sectional network | Edge weights, node predictability, primary centrality; bridges only for justified communities | Node audit, edge CIs, centrality/bridge case-drop stability | Predictability-ring network, centrality, relevant bootstrap/bridge plots | Undirected conditional associations, not causal effects |
| Cross-sectional comparison | Group-specific edges/centrality plus between-group differences | NCT structure/global strength, planned edge tests, planned node-centrality tests with correction | Both networks and edge/centrality difference views | Independent groups, matched nodes/settings; omnibus and local tests are distinct |
| CLPN | All lagged coefficients, AR diagonal, off-diagonal cross-lags, in/out indices | Edge uncertainty and case-drop stability of directional indices; transition/missingness audit | Spring directed network plus separate incoming/outgoing influence | Prospective prediction at sampled lag; not automatically within-person or causal |
| Cross-sectional NIRA | Baseline and target-wise projected outcome, effect, uncertainty, rank stability | Fixed-edge/moderation prerequisite; distinguish exact+bootstrap from MC+permutation | Separate alleviating/aggravating comparisons where prespecified | Model-based projection, not treatment efficacy |
| Dynamic KimNIRA | Temporal J/h and between-person network separately; stationary and finite-time intervention effects, direct/spillover, target ranks | Contemporaneous dependence; supported lag-order check; mixing/stationary landscape; participant-bootstrap rank stability | `kimPlotNIRA()` plus time-course trajectory | Conditional on synchronous first-order KIM and timing assumptions; not clinical effectiveness |

Do not add generic covariate nodes to any symptom network when covariates are intended only as confounder controls. For the user's cross-sectional plugin, covariate handling is a separate documented estimation option, not an additional network-analysis type.
